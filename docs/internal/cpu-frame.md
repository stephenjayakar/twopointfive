# The CPU frame — hill-climbing Game.update + BoxWorld.upload, identity-neutral (lane exp/cpu-frame, 2026-08-16)

**Summary (M4 Max, bun headless — tools/cpu-frame/bench.ts, 1200 timed frames after 300 warm, seed 1 / seed 2; base a41c308e → lane acac421d):**
1. `Game.update` p50 **0.41–0.43 → 0.26 ms** (−37 %), p90 0.53–0.57 → 0.32–0.34, p99 1.4–1.6 → 0.6, mean 0.45–0.48 → 0.28–0.29; max frames 2.6–3.4 → 2.7–2.8 ms (the tail is not GC: see § What is left).
2. `BoxWorld.upload` p50 **0.37 → 0.21 ms** (−43 %), p99 0.43 → 0.33. The whole step (update + camera + lights + upload) p50 **0.77–0.80 → 0.48 ms**, p99 1.8–2.0 → 0.9–1.0.
3. Allocation **720 / 578 → 57 / 56 KB a frame** (−92 %; heapTotal growth over 10-frame windows after a full GC — bun:jsc memoryUsage().current, which Lane H's table read, is the process high-water mark and never shrinks; process.memoryUsage().heapTotal between GCs reads 0 while the heap has spare blocks — neither measures churn, the windowed measure does).
4. Every change is identity-neutral, proven per commit: the packed TABLE BYTES hashed after every upload of a scripted 300-frame run (door flung / shut, a prop shoved, a static hidden and restored, a fixture dimmed, a marking gain moved, the markings and glass switches flipped) equal the pre-change recording (`tables-hash.ts --check docs/perf/cpu-frame-tables.json`); every character's skinning matrices + proxy records hashed per frame over 1500 / 2400 frames × 3 seeds equal the base build's (`pose-hash.ts`); the raycast walk equals the brute force on 500 000 rays (index, t, normal) and the scalar rayBox its array form on 500 000 single-box tests (`raycast-diff.ts`); `gait.ts --json` byte-identical; journal-fixtures (3 sessions), needs- / civilians- / tactics-identity, `probes.ts player`, tour, soak green; the browser: `rig-identity.js __idrun` at high hashes corr3 958b39a5 · lobby4 741f24e4 · cub2 ced41bc9 · cubicles b60e3876 on both builds served side by side (a41c308e on :5262, the lane at 95a83f39 and again at acac421d on :5261), no console errors, 6 s of scripted play after.
5. Sites: (i) `BoxWorld.raycast` walks the statics through its own padded 2D cell grid (globals + the dynamic tail brute-forced as before): raycast 13.3 → 7.4 % of the frame — the rest is the ~310 dynamics, still tested one by one (candidate below); (ii) `PoseFK.run` in place, `SkeletonInstance.update` over scalars, `parentRot` / `rotateModel` / `rotateLocal` / `setModelRot` over scalars, twoBoneIK's re-runs restricted to the limb's subtree, `rayBox` / `rayBoxRot` over scalars — the animation's allocation is gone and character.update fell 33.7 → 30.9 % of a frame 38 % shorter; (iii) upload packs a static only where its inputs moved (a per-index shadow of every pack input compared each frame — no writer flag to forget), caches the statics' half of the trace-grid registration, and takes a `gridEnabled` switch (the native host may set it false: no cells / items / globals built or uploaded; the CPU raycast has its own grid) — upload 0.37 → 0.21 ms, of which the compare loop is now the biggest single piece (~85 µs).
6. `lifeLayer`'s second FK solve is NOT redundant (the pose changed at the hips between the two: every joint moves) — left; what was redundant were three of twoBoneIK's four full re-runs.
7. Negatives / not shipped: caching cos/sin per dynamic box (a WeakMap or a hidden field on Box — the ~40 ns a test it would save is not worth mutating strangers' objects); a per-frame grid over the dynamics (their Box objects are mutated in place between upload and the raycasts — a grid built at upload would not see the moved leaf: not identical); reusing rig-prop Box objects across frames (the stale-`all` raycast would then see current positions: not identical); a sampleClip segment hint (needs a field on gltf.ts's Track — not this lane's file); replacing Math.hypot (different rounding).
8. Instruments (all under tools/cpu-frame/): `bench.ts` (percentiles + the windowed allocation), `tables-hash.ts` (+ the recording docs/perf/cpu-frame-tables.json), `pose-hash.ts` (+ docs/perf/cpu-frame-pose.json, recorded on a41c308e), `raycast-diff.ts`; numbers in docs/perf/cpu-frame.json.
9. `bun --cpu-prof` over bench.ts + tools/cpu-frame/cpuprof.ts (`--under stepOnce`) is the profile; the top of the frame now: upload 41 % (compare loop, the dynamics' pack, the grid scatter), skeleton.update 15 % (pure mat4 math), rayBox 6 % (the dynamics), buildGrid 8.5 %, sampleClip 4.5 %, hypot 3.6 %.
10. Nothing outside src/scene/boxes.ts, src/anim/skeleton.ts, src/math/vec.ts changed; the two Box-world switches the native host may flip are `BoxWorld.gridEnabled` (default true) and — unchanged — nothing else; character.ts / devices.ts / player.ts were audited (below), not edited.

## 1 · Method

- **Bench** (`bun run tools/cpu-frame/bench.ts [--seed N] [--json p]`): the QA harness's Game (tools/qa/headless.ts standUp — the fake device, the null smoke, the real Game / characters / collision), seeded (`Math.random = mulberry32(seed·7919+13)`), stepped like main.ts (game.update → camera → lights → world.dynamics → upload) under a seeded key script (a random walk 1‥4 s a leg, sprint a third of the time, a crouch press now and then, the cursor moved every 97 frames — the aim ray runs at (800, 500) as in every probe; the two laser tripwires, guards and civilians live). Per frame `performance.now()` round update / upload / the whole step; percentiles over the last 1200 of 1500 frames. Allocation: after the timed run, 30 windows of 10 frames each preceded by `Bun.gc(true)`; the window's `process.memoryUsage().heapTotal` growth ÷ 10 = KB a frame (block-granular; JSC trims the capacity to the live set on a full GC, and grows it as the window allocates).
- **Profile**: `bun --cpu-prof --cpu-prof-dir <d> --cpu-prof-name x.cpuprofile tools/cpu-frame/bench.ts --frames 3000 --quiet` → `bun tools/cpu-frame/cpuprof.ts x.cpuprofile --under stepOnce --top 30 --incl '<regex>'` (self / inclusive), plus a small callers script for one leaf (which caller pays for quat.mul: 85 % of it was PoseFK.run under twoBoneIK / lifeLayer).
- **Identity per commit** (the order they were run): `bun run typecheck` · `tables-hash.ts --check` · `pose-hash.ts --check` · `raycast-diff.ts` · `probes.ts journal-fixtures needs-identity civilians-identity tactics-identity` · `probes.ts player` · `tour.ts --runs 1 --quiet` · `soak.ts --seeds 1 --minutes 3 --quiet` · the browser `__idrun` at high against the base tree served on its own port (5262; the lane on 5261). The base tree for cross-build claims = a detached worktree of a41c308e with the instruments copied in.

## 2 · Finding 1 — the raycast (boxes.ts)

Before: `for (const b of this.all) rayBox(ro, rd, b, best)` over ~1100 boxes, called for the two laser tripwires (devices.ts:238, skipFlags NoShadow), the cursor's aim ray (player.ts:1289, skipOwner PLAYER_ID) and a dazzled man's laser dot (combat.ts:304): 23 % of Game.update in H's profile, 13.3 % of the whole frame in this bench (rayBox self 11.6 %).

The walk: `all` = the STATICS (as of the last upload — the game raycasts between uploads, so `all` is a frame old and its dynamic Box objects may have moved since; the brute force read whatever those objects hold NOW) + the dynamics. Statics never move (the editor rebuilds the list and the shadow below sees any moved box), so they get their OWN grid, built in upload() when the static prefix changed: every static registered whatever its flags (skipFlags are judged per query exactly as before — a static hidden by destruction and restored later is still findable; a Glass pane IS a hit unless the caller skips Glass — panes are registered like anything), footprint padded `RAY_PAD` 1 mm each side so a face lying on a cell line is in both cells (which is also what makes the early exit exact under the DDA's accumulated crossing-t rounding); a static reaching outside the 40 × 28 grid or covering > 96 cells is a GLOBAL tested every ray (10 in the office). `raycast()`: the dynamics (all[nS‥)) and the globals first (they tighten `best`), then a 2D DDA from where the ray enters the grid, each cell's statics tested once per ray (a stamp array), stopping when the next cell begins past `best` — a static's entry point lies inside a cell it is registered in (the padded footprint contains it), so nothing nearer can be beyond. The per-box test is `rayBox(ro, rd, b, best)` as before (t is `t0`, unaffected by the tmax the box was tested with; a null differs only where the box would have been rejected anyway), so the hit's t and normal are the same bits; what changed is the candidate SET and the ORDER — the brute force's `r.t < best` gave the FIRST index a tie, kept explicitly as `r.t === best && i < bi` (and the glassOpen hook consulted at that point as before). Rays that never enter the grid / start off it / run vertical are handled (clip, clamp, the one-cell case). Grid stats: 782 statics, 10 globals, 2900 items.

Then `rayBox` / `rayBoxRot` themselves were written out over scalars (the slab loop unrolled over the three axes, quat.rotate's expression for the rotated frame — the same statements in the same order): 500 000 single-box tests against the array form kept inside the test agree bit for bit (t and n). Proof of the walk: `raycast-diff.ts` — 100 000 rays (seed 1) + 400 000 (seed 2): random origins in and about the world, near-horizontal body-height rays, axis-aligned rays from INTEGER coordinates (along cell lines, onto faces), rays aimed about a box, rays exactly onto a +x face, a third with unnormalised directions, every skipFlags / skipOwner shape the game uses, tmax 0.3‥1e9; through calm play, a door flung open, a static hidden the way destruction hides one, one pane holed through `glassOpen`, everything restored, the raycast between uploads (a moved leaf under a stale list) and after a frame with no upload — 0 differences (34.4 % of the rays hit). Cost: raycast 13.3 → 7.4 % of the frame; rayBox's remaining 5.7 % is 84 % the dynamics (~310 a ray).

## 3 · Finding 2 — the animation's allocation (skeleton.ts, vec.ts)

Before: `PoseFK.run` allocated five arrays a node (r, the local offset, its rotation, the new rot, the new pos) × 55 nodes × ~30 runs a man a frame (twoBoneIK runs it four times per limb; lifeLayer / sneak / carry / long-gun / wall / throw layers run it before their IK); `quat.mul` alone was 15.7 % of the frame (85 % of it under PoseFK.run: 67 % via twoBoneIK, 12 % via lifeLayer); `SkeletonInstance.update` built r / t / s arrays a node + a subarray a joint; `Character.turn` → `parentRot` allocated two arrays a level up the chain, `rotateModel` five more.

Now: `PoseFK.rot[i]` / `pos[i]` are the SAME arrays every run, overwritten with quat.rotate's / quat.mul's arithmetic operand for operand; `runFrom(pose, root)` recomputes only root's subtree; `SkeletonInstance.update` reads the pose as scalars and writes the parent·local product into a fresh `globalRot[i]` (still one array a node — its readers may alias it; left), `m4.fromTRSs` over scalars (the same expressions), the joints' inverse-bind and jointData slices as views made once; `parentRot` writes ONE shared scratch quaternion (its two callers consume it inside one expression); `rotateLocal / rotateModel / setModelRot` are the nested quat.mul / conj / normalize written out over scalars, expression for expression.

**The audit that made in-place safe**: every `fk.pos[…]` / `fk.rot[…]` read in character.ts (and gait.ts) was walked: the layers that keep a joint across a run already copy it (`v3.copy`, `[...q]` — foot spots and soles in every foot layer, the hands and chest in longArms / sneak / throw / grab); every remaining raw capture is consumed before the next run (lookAt's `hr`, softKnees' `ph / pk / pa` into `tgt`, runPlant's `tp / ap` into the target literal, longBody's shoulder line, the signal / door layers' `sh / nk` into literals, wallArms' hips into scalars, pivots()' P2 / P3 inside the closure's own body) or is of a node the run leaves as it was (carryArms' `chest` = spine3 and `rL0` = the left hand across the RIGHT arm's IK: neither node's inputs move, so a full run would write them the same numbers; twoBoneIK's own `pRotA` across its re-runs likewise). `SkeletonInstance.globalRot` readers all consume immediately (conj / mul / rotate → fresh). Then the empirical net: pose-hash (every character's jointData + every proxy record, per frame, over the bench script + digit / E / G / RMB presses so the sneak, carry, long-gun, aim and throw layers all solve) identical to the base build over 1500 (seed 1) and 2400 (seeds 2, 3) frames; gait.ts --json byte-identical; the identity probes / fixtures / tour / soak green; `__idrun`'s four stills hash alike in the page.

twoBoneIK: its FIRST run stays a full run (whatever the caller left stale is current from there — the documented precondition is not relied on); the re-runs after its own edits of a / b / c are `runFrom(a)` / `runFrom(c)`: every other node's inputs did not move since that full run, so a full run would write them the same numbers they already hold. lifeLayer's own second solve (after the hips shift / turn, before the feet are put back) is required — the pose changed at the root of everything.

## 4 · Finding 3 — upload (boxes.ts)

Before: 782 statics re-packed every frame (4 trig calls a box, the f16 pack, matWord, the marking slot lookup, 24 words) + `buildGrid` re-registering every static (footprint trig, heightExtent, yLevel, the f16 slack) = ~60 % + 22 % of 0.37 ms.

Now: (a) **the static slice packed only where its inputs moved** — `statShadow` holds per INDEX every input the pack reads (c · yaw · h · flags · owner · albedo · emissive · cutHeight · matWord · markGain · rot present + 4 · marks length; the marks array's IDENTITY beside it) and a static whose reads equal its shadow keeps the words it packed before (only this class writes the geo / mat arrays); anything else — a hidden static, a dimmed fixture, a moved editor box, a replaced Box object with other values — is repacked on the spot; the marking table's state is an EPOCH (`packEpoch`, bumped by repackMarkings / resetMarkTable) and the markings switch a stored flag: either moves and every static repacks. Writers need raise no flag: the compare is the truth (~25 field reads a box). The visible prefix is rebuilt from the flags every frame (a flag test a box), `marked` counted from a per-box byte. (b) **the statics' half of the trace-grid registration cached** (`gridRegister` factored out verbatim; per static its cell range, quantised height, mask bits, global-ness, slack) and rebuilt only when (a) said a static changed or the count changed; buildGrid scatters statics from the cache and registers the dynamics as before (globals still in index order under the 16 cap: statics' first). (c) **`gridEnabled`** (default true) — false = no cells / items / globals built or uploaded; SceneInfo's header, globals rows (zero), capsule words, the rig fit and the capsule / info uploads still happen (`finishInfo`); the CPU raycast has its own grid and works either way (smoke-tested headless: the same hit with it off, info[0..3] / [20..23] sane, back on = as before).

Bytes: `tables-hash.ts` — geo / mat / mark table / visible / cellStart / items / SceneInfo / capsules hashed after every one of 300 uploads (FNV over exactly the ranges upload writes) under a script that exercises every path (door flung + slammed, Sam walked into a prop, static hidden + restored, fixture dimmed + restored, markGain moved + back, markings off + on, glass off + on) — identical to the recording made before any change (`docs/perf/cpu-frame-tables.json`, at 353f32f4). Cost: upload 0.37 → 0.21 ms (0.24 after (a), 0.21 after (b)); the compare loop is now ~85 µs of it (100 ns a static — the office's statics come in 8 hidden-class shapes, JSC's polymorphic limit, so the ~14 property loads a box are borderline megamorphic).

## 5 · What is left (the profile at 95a83f39 — before the scalar rayBox, which took ~1.5 % more off; % of the frame under stepOnce)

upload 41 % (self 22 %: the compare loop ~85 µs, the dynamics' loop + `packBox` ~30 µs, mkey Map sets ~15 µs; buildGrid 8.5 %: the scatter / prefix sum / chamfer / region B over 1120 cells + the dynamics' registration) · `SkeletonInstance.update` 15 % (mat4 math: 55 fromTRS + mul, 53 × 2 skinning muls a character — ~40 ns a mat4 mul, near the JS floor) · rayBox 5.7 % (the dynamics: 3 rays × ~310) · sampleClip 4.5 % · hypot 3.6 % · civilians' updateOne 12 % (their character.update).

Candidates NOT shipped, each with why:
- a writer-side `staticsDirty` in place of the compare (saves ~85 µs a frame): fragile — every present and future writer of a static's fields (destruction, lighting's supply factors, the weather's wet lot, the editor, glassbreak…) must remember it, and a forgotten one is a stale table with no detector; the compare is the detector. If wanted later: keep the compare as an audit every N frames.
- cos / sin cached per dynamic box: a WeakMap costs what it saves; a hidden field on Box mutates objects this class does not own.
- a per-frame dynamics grid for the raycast: NOT identity-neutral (the dynamics' Box objects move between upload and the raycasts; the brute force reads them as they are at the call).
- rig-prop Box reuse across frames: NOT identity-neutral (the stale-`all` raycast semantics).
- sampleClip's binary search with a per-track hint: needs a field on gltf.ts's Track (another lane's file); ~1–1.5 %.
- `Math.hypot` → sqrt of the sum: different rounding, not neutral.
- `SkeletonInstance.globalRot[i]` in place (one array a node a frame remains, ~400 a frame): its override branch ALIASES the ragdoll's `ov.rot` (a reader between the ragdoll's write and the next update would see the new value; a copy would not) — a pool for the plain branch + the alias for the override branch would keep that; ~15 KB of the remaining 57.
- the max frames (2.6–3.4 ms, unchanged): not the animation's GC (allocation −92 % moved nothing there) — the tail is bursts inside Game.update (path planning, a search plan dealt, the guards' hearing pass over many events); a per-frame section timer inside update would name them (not started).
